## Codebase Patterns
- The PRD's ralph branch must be created from feature/samsung-sensor-sdk, not main:
  main (40c04a2) predates the Samsung Health Sensor SDK integration, so it lacks
  SamsungSensorMonitor.kt / SensorConnectionManager.kt / Hrv.kt that this PRD's
  debug trackers depend on. Branch ralph/sensor-capability-debug-screen was cut
  from feature/samsung-sensor-sdk instead.
- New debug-only sensor code lives in br.unioeste.pulselab.wear.data.health.debug,
  separate package from br.unioeste.pulselab.wear.data.health so existing production
  monitor/connection files are never touched.
- SensorTracker<T> (data/health/debug/SensorTracker.kt) is the shared interface:
  trackerType (HealthTrackerType), isContinuous flag, isSupported(connection)
  default method checking connection.supportedTypes(), and
  readingFlow(connection): Flow<T>. Each new tracker class implements this.
- Capability-gate pattern to copy for every tracker (from SamsungSensorMonitor.kt:157-187):
  check `type in connection.supportedTypes()` before calling connection.tracker(type),
  log a warning and skip otherwise. Never assume a tracker type is available.
- Verification for this project's non-UI Kotlin classes: `./gradlew :wear:compileDebugKotlin -q`
  is enough — no device/emulator needed until UI stories (US-007/US-008) which
  require @WearPreviewDevices previews instead.
